- When updating or installing a new Syncode/OpenCode desktop build (deploy-prod.ps1, deploy-dev.ps1, or any equivalent install), always launch scripts/verify-prod-install.ps1 in a visible terminal window at the end so windro can see the install result without asking the agent (the agent lives inside OpenCode). The verification window must stay open until dismissed.
- Never run `opencode upgrade`, `bun upgrade`, or any install/upgrade path that pulls from upstream anomalyco/npm/GitHub releases. Updates must come from windro-exe/Syncode only: dist branch (CLI/TUI) and GitHub releases (desktop), via scripts/release.ps1 or syncode-release.yml.
- Every release must publish to BOTH update feeds: scripts/release.ps1 (local) or syncode-release.yml (CI). dist/version.json + binaries must always match the latest released version — never ship a build without updating the feeds, or the in-app updaters go silent.
- SYNCODE_VERSION must stay semver-ABOVE upstream releases and must match the version.json published on the dist branch. Never "fix" the stamp down.
- Preserve the local .syncode/rules/rules.md across branch merges (backup/restore) — it holds the live rules; the repo tracks a placeholder. A prod merge will otherwise clobber it.
