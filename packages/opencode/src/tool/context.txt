Show where the context window is being spent right now: how full it is, the real token usage of the last request, and an estimated per-category breakdown.

Use this when:
- You want to know how much context budget is left before older turns get evicted.
- The user asks about context usage, token usage, or why the window is filling up.
- You are deciding whether to persist state to memory or wrap up a long session.

Takes no parameters. Reports:
- Window usage (used / limit) and the usable budget.
- The 60% soft-checkpoint and 80% eviction thresholds and whether you have crossed them.
- The last request's real token counts (uncached input, cached read/write, output) and the cache hit rate.
- An estimated split of the conversation: visible text vs tool output, system+tools overhead, and how many turns have been evicted (recoverable with session_recall).

The per-category breakdown uses a real BPE tokenizer (o200k_base) — close for English/code and far better than a char heuristic, though still a proxy that won't exactly match the provider's tokenizer (e.g. Claude). The window-usage and last-request numbers are the provider's real figures.
