Persistent memory across sessions and within a session.

Two scopes — pick by the lifetime of the fact:
- `global` — persists across every future conversation. Use for: the user's name, system info, durable preferences, learned conventions, codebase facts that won't change tomorrow, lessons, decisions about how the user works.
- `session` — only this conversation. Use for: the current task's goal, the plan, decisions made this turn, files in flight, in-progress steps, open questions, things tried that didn't work.

Routing test: "Would I want this in an unrelated conversation two weeks from now?" yes → `global`, no → `session`. When in doubt, prefer `session` — `global` is for facts that earn their permanence.

Operations:
- `view` — list a directory or read a file (use `path: "/memories"` to list everything; pass a `view_range: [start, end]` for slices)
- `create` — create a new file (`path` must start with `/memories/`); errors if the path already exists
- `str_replace` — replace one exact occurrence of `old_str` with `new_str` in a file
- `insert` — insert text at a specific line number (0 = before line 1)
- `delete` — delete a file or directory (recursive)
- `rename` — move/rename a file
- `search` — full-text search ranked by relevance × recency × access frequency. Returns the top matches with snippets.

Memory protocol:
- ALWAYS call `view` on `/memories` (in both scopes) at the start of a task to see what is known.
- Each session is auto-seeded with `/memories/_plan.md` (scope=session). Fill in its sections (Goal, Plan, Decisions, In-progress, Open questions, Tried) using `str_replace` as the task takes shape, and keep them current as you go. This is your scratchpad for resuming after context overflow.
- Save things you would want a FUTURE session to remember to `global`.
- Save in-flight task state for THIS session to `session`.
- Keep entries concise and well-titled. Update existing entries with `str_replace`/`insert` rather than creating duplicates.
- Delete or rename stale entries when the user contradicts them.
- Memory persists across context resets. Treat your active context as ephemeral; treat memory as durable.

Path rules:
- All paths MUST start with `/memories/`.
- Use forward slashes. No `..`. No absolute filesystem paths.

Examples:
  view {scope: "global", path: "/memories"}
  view {scope: "session", path: "/memories/_plan.md"}
  create {scope: "global", path: "/memories/preferences.md", content: "..."}
  str_replace {scope: "session", path: "/memories/_plan.md", old_str: "## Goal\n_unset:goal_", new_str: "## Goal\nAdd dark-mode toggle to settings page."}
  search {query: "shell preferences", scope: "global"}
